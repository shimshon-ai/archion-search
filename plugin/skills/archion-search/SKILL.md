# Archion Search — методика агентного поиска по архиву

**Версия методики: 1.1.0.** В КАЖДЫЙ вызов `search_archive` передавай параметр
`skill_version: "1.1.0"`. Если в ответе сервера есть поле `notice` — покажи его
пользователю дословно (обычно это просьба обновить плагин) и продолжай работу.

Сервер — тонкий: он только исполняет векторный + полнотекстовый запрос к Qdrant `archion_v3`
(1 610 808 чанков, 14 языков) и отдаёт чанки. Вся интеллектуальная работа — твоя:
расширить запрос, оценить выдачу, переформулировать, отобрать. Один вызов «в лоб» почти
всегда даёт посредственный результат; методика ниже — как получить сильный.

## Инструменты

**`search_archive`** — поиск. Параметры (точные имена сверяй со схемой инструмента в сессии):
- `dense_query` — запрос для векторного поиска (см. §1);
- `exact_terms` — список (list, не строка через запятую) редких терминов/имён для точного полнотекстового recall;
  фразы из 2+ слов работают как compound и весят сильнее одиночных слов;
- `skill_version` — всегда `"1.1.0"` (версия этой методики, см. шапку);
- фильтры: `language` (ru/he/en…), `result_type` (units/sources/posts), `is_original`,
  `has_transcript`, `date_from`/`date_to` (YYYY-MM-DD), `exclude_content_types` (напр. CLIP), `limit`.

Выдача сгруппирована по `mdb_uid` (беседа/юнит). Каждый чанк несёт: `chunk_text` (сам текст
фрагмента — готовая цитата), `title`/`full_title`, `content_type` (LESSON_PART,
VIDEO_PROGRAM_CHAPTER, CLIP…), `effective_date`, `chunk_index`/`total_chunks` (≈ позиция
фрагмента внутри беседы), `mdb_uid`, `media_url` (страница на kabbalahmedia.info), score.

**`resolve_unit`** — метаданные и файлы юнита по `mdb_uid`: название, дата, длительность,
файлы по языкам (rus mp4/mp3, docx-транскрипт, heb-оригинал). Вызывать только для
финалистов отбора, не для каждого хита.

## 1. Расширение запроса — всегда, перед первым вызовом

Никогда не передавай запрос пользователя в `dense_query` дословно. Два канала, у каждого своя работа:

**`dense_query`** — 1–3 предложения живым языком, как человек *проживает* вопрос, а не как
он его формулирует терминами. Не список ключевых слов, а маленькая сцена состояния:

- Плохо: `пустота после достижения цели смысл жизни`
- Хорошо: `Человек добился всего, к чему шёл годами, — и внутри стало пусто. Почему успех
  не наполняет и что это за пустота, которая приходит именно после достижения?`

**`exact_terms`** — 3–7 редких терминов, имён, названий источников: то, что должно
встретиться в тексте дословно. Это независимый канал recall — полнотекстовый индекс находит
редкие термины там, где эмбеддинг их размывает. Частотные слова («человек», «жизнь»,
«мир») не давать — только шум. Пример: `наполнение, келим, Бааль Сулам, точка в сердце`.

## 2. Температурная модель языка

| Температура | Язык | Когда |
|---|---|---|
| 🧊 Холодный | язык боли человека, не знающего о каббале: «почему мне ничего не хочется», «тревога без причины», «всё есть, а радости нет» | контент для широкой аудитории; поиск того, как Рав отвечает на житейский вопрос |
| ♨️ Тёплый | терминология: «исправление желания», «АХАП», «ло лишма», имена источников | точное попадание в терминологические пласты; вопросы учеников |

**Опасность эхо-камеры:** искать только знакомыми формулировками = находить только уже
найденное. Тёплый язык приводит в одни и те же лекционные пласты; холодный вскрывает беседы,
где Рав отвечает «человеку с улицы» его словами. И наоборот: чисто холодный запрос может не
достать глубокие терминологические места.

Как ломать эхо-камеру:
- температура `dense_query` — по задаче пользователя, а не по привычке;
- терминологию класть в `exact_terms`, оставляя `dense_query` живым — так работают оба пласта сразу;
- между итерациями менять температуру: если тёплый запрос дал «всё то же самое» — переписать холодным, и наоборот.

## 3. Петля поиска (2–4 итерации)

```
запрос → оценка выдачи ПО ТЕКСТУ чанков → диагноз → переформулировка → запрос → …
```

Оценивай выдачу чтением `chunk_text`, а не по score. Диагнозы и ходы:

| Симптом | Ход |
|---|---|
| Мимо темы | сменить угол `dense_query`: другая сцена, другой субъект (не «почему пусто», а «что человек ищет на самом деле») |
| Всё из одной-двух бесед | сменить температуру; убрать/заменить `exact_terms`, которые тянут в один пласт |
| Бедно, мало хитов | ослабить фильтры; расширить `exact_terms` синонимами-терминами; попробовать иврит (§4) |
| Слишком общо, «вода» | добавить редкие термины в `exact_terms`; конкретизировать сцену в `dense_query` |
| Нашёлся сильный ответ | **перефрейм**: извлечь ЕГО рамку ответа и сделать производный запрос |

**Перефрейм — двигатель расширения.** Рав почти всегда переворачивает вопрос («тревога —
раскрытие пустоты желания»). Производный запрос из его рамки находит пласты, недостижимые
из исходной формулировки. Один перефрейм-заход в петле почти всегда окупается.

Правила петли:
- `dense_query` и `exact_terms` менять **независимо**: часто выдачу чинит замена только
  `exact_terms` при том же `dense_query` (и наоборот);
- **rate limit сервера — 30 вызовов/мин**. Не стрелять очередями запросов «на всякий случай»:
  каждый следующий вызов — после чтения и диагноза предыдущей выдачи. Норма — 2–4 вызова
  `search_archive` на задачу, `resolve_unit` — только для финалистов;
- после 3–4 итераций без улучшения — остановиться и честно показать лучшее из найденного
  с оговоркой, а не крутить петлю дальше.

## 4. Приём ru+he: искать на иврите, файлы брать русские

Смысловое ядро корпуса — иврит (язык оригинала): поиск на иврите находит точнее, особенно
терминологические и тонкие места. А файлы юнита существуют на русском.

Когда применять: две русские итерации дали бедную выдачу; тема терминологически тонкая;
нужен максимальный recall по важной задаче.

Как:
1. Переведи на иврит **смысл**, не слова: `dense_query` — живой ивритской фразой,
   `exact_terms` — ивритские термины (לב, רצון לקבל, תיקון…);
2. `search_archive` с `language=he`;
3. Для найденных `mdb_uid` — `resolve_unit`: у того же юнита есть русские файлы
   (rus mp4/mp3, docx). Ивритский `chunk_text` цитировать пользователю с переводом смысла
   и пометкой, что точная русская формулировка — в русской дорожке юнита.

## 5. Фильтры под задачу

| Задача | Фильтры |
|---|---|
| Фрагменты живых бесед/уроков (сырьё для клипов) | `result_type=units`, `language=ru`, `is_original=true`, `exclude_content_types=CLIP` (готовые клипы уже публиковались — мимо) |
| Готовые нарезанные клипы архива | `result_type=units`, content_type CLIP **не** исключать |
| Короткие микро-беседы (~3 мин, «Беседы в Пути») | `result_type=units` + предпочитать `content_type=VIDEO_PROGRAM_CHAPTER`, длительность проверять через `resolve_unit` |
| Готовые короткие тексты Рава (блог) | `result_type=posts` — текст без видео и транскрибации |
| Первоисточники (Бааль Сулам, Рабаш…) | `result_type=sources` |
| Свежесть / сезонность / период | `date_from` / `date_to` |
| Гарантированный текст фрагмента | `has_transcript=true` |
| Оригинальная речь, не перевод озвучкой | `is_original=true` |
| Трудный/тонкий запрос | `language=he` + `resolve_unit` → русские файлы (§4) |

## 6. Отбор и ранжирование — под задачу пользователя, не по score

Score — грубый префильтр (слабое сервер уже отсёк порогом), внутри выдачи он НЕ ранжирует
«что лучше для задачи». Критерии отбора, в порядке важности:

1. **Релевантность задаче** — отвечает ли фрагмент на вопрос пользователя по существу,
   а не совпадает словами.
2. **Завершённость мысли в `chunk_text`** — фрагмент начинается и заканчивается мыслью,
   а не обрывком; чанк — механическая нарезка, его границы ≠ границы мысли. Обрывок
   с сильным ядром можно взять, пометив «мысль продолжается за границей фрагмента».
3. **Дедуп** — близкие чанки одной беседы (тот же `mdb_uid`, соседние `chunk_index`) —
   один кандидат: брать лучший, остальные упомянуть как контекст.
4. **Разнообразие** — разные беседы, годы, типы контента; три фрагмента одной беседы —
   почти всегда хуже трёх фрагментов из разных.

## 7. Формат ответа пользователю

По каждому выбранному фрагменту (обычно 3–7):

```
### «Первые слова цитаты…»
> chunk_text — дословно; длинное сокращать […], но не перефразировать
- Юнит: full_title (effective_date) — mdb_uid: XXXXXXXX
- Ссылка: media_url
- Позиция: чанк 12/40 ≈ первая треть беседы
- Почему: одна строка — чем фрагмент отвечает на задачу
```

В конце — короткий блок «Отброшено»: 1–3 строки о том, какие пласты выдачи отсеяны и почему
(«ещё 4 хита из той же беседы — дубли», «лекционные фрагменты 2003 — слишком терминологично
для холодной аудитории»).

Если после честной петли достойного нет — так и сказать: чего не нашлось, какие
формулировки пробовал, что можно уточнить. Не натягивать слабые фрагменты.

## 8. Ограничения

- **Rate limit: 30 вызовов/мин** на всё (search_archive + resolve_unit). Петля —
  «запрос → чтение → диагноз → запрос», не парные/пакетные залпы вслепую.
- Доступ read-only: сервер ничего не пишет и не скачивает; файлы юнита пользователь
  берёт сам по ссылкам из `resolve_unit`.
- `media_url` ведёт на страницу юнита kabbalahmedia.info, не на прямой файл.
- Метаданные бывают неточны (длительность, язык-теги) — критичное сверять по `resolve_unit`
  и здравому смыслу.
